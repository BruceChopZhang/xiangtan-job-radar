# 湘潭招聘雷达

透明、可追溯的个人招聘公告监测工具。第一阶段：Python 3.11+ 标准库 + SQLite + 静态 HTML，无第三方Python依赖，无API费用。代码MIT许可，官方招聘内容权利归原发布方。

## 可行性与边界

3个官方栏目于2026-10-21实际GET核实为HTTP 200，网址见 sources.json。市人社局招考资讯、湘潭县考录招聘、雨湖区教育局信息公开栏目（综合栏目，只保留标题含招聘/选调/遴选/人才引进/招募的记录）。这不是湘潭全域覆盖，暂未接入湘乡、韶山、岳塘；每天只读取每栏首页，较长停机可能漏掉翻页公告。市人社局和县栏目均约50条，雨湖教育栏目约15条。网站可随时改版或限制访问。

先把可靠获取和失败可见做稳，再增加翻页、附件解析、资格初筛和周报。第一阶段不判断是否正在报名，不把拟聘用公示当新岗位，不输出个人条件或资格结论。附件只提取常见扩展名链接，不下载、不读取内容；动态下载链接和图片可能遗漏。

## 零基础：手动运行

1. 安装Python 3.12（Windows安装时勾选 Add Python to PATH）。解压项目到一个固定文件夹。
安装后也可以直接双击 `run.bat`：先测试，再抓取，最后打开网页；窗口会保留错误信息。首次运行仍建议了解以下步骤。

2. 打开该文件夹，在地址栏输入 `cmd` 并回车。确保能看到 README.md 和 sources.json。
3. 输入 `python --version`；如Windows找不到python，试 `py --version`，以后命令也把python替换为py。
4. 输入 `python -m unittest discover -s tests -v`。应全部通过。
5. 输入 `python -m radar`。串行访问每个正文，可能需要几分钟；不要反复启动。遇到超时会继续其他来源。
6. 双击 `site/index.html` 打开仪表盘。无需服务器。
7. 再运行同一命令会保留历史、首次发现时间，同链接不会新增重复记录。

Linux/macOS可用python3代替python。无需pip安装依赖。没有后台常驻任务：关闭电脑后，本地不会继续监测。

## 怎样判断是否真的运行、是否失败

- 页面顶部生成时间是最近一次生成时间，来源卡片是最近一次访问结果。超过48小时未更新应检查任务；静态页面不会自行刷新日期。
- “成功”只说明栏目本页结构可识别；“成功：本页无关键词公告”仅指这一个页面没有命中标题关键词。
- “失败”：HTTP失败、超时、验证码、栏目标识缺失或未识别出带日期公告行。信息未知，绝不能解释为无岗位。
- “正文处理中”：本轮列表已读取，正文请求尚未结束，不能当作全部完成。运行时可刷新网页查看逐条日志。
- “部分失败”：列表成功但有正文失败或遇限制停止正文处理。看下方“正文”日志和公告附件状态。旧附件保留并标记可能过期。
- HTTP 200不等于成功：也可能是错误页或网站改版。HTTP为空表示没有取得响应，如DNS、TLS、网络或超时错误。
- 日志逐条包含来源、请求网址、访问时间（北京时间）、HTTP状态、抓取条数、错误、秒数。栏目条数是关键词公告数，不是岗位数；正文条数是附件链接数。
- 命令退出码0表示本轮请求及解析均完成，1表示有失败；失败也会生成网页和日志，历史公告不会清空。
- `data/logs.json` 可用记事本查；`data/radar.sqlite3` 保存公告、来源关联、修订、日志；`data/snapshots`按SHA256保存原始HTML。日志snapshot字段对应本地证据。不要编辑数据库。
- 内容同链接修订会更新显示，并保留修订记录。去重按规范化官方链接；不同网址转载仍保留，避免误合并。

每周备份整个data目录。恢复时将备份data放回原项目，再运行。删除data会丢失历史及首次发现时间。

## GitHub部署版：仅手动运行

目标仓库：https://github.com/BruceChopZhang/xiangtan-job-radar 。当前交付仅是部署准备，尚未在该仓库运行或发布；没有定时触发器，也没有push触发器。

上传的是项目根目录内的文件和文件夹（必须包括 `.github/workflows/radar.yml`），不要上传ZIP本身，也不要再套一层文件夹。详细核查见 `DEPLOYMENT.md`。

首次配置：仓库 Settings → Pages → Source 选择 GitHub Actions。然后在 Actions → 湘潭招聘雷达 → Run workflow 手动运行。工作流声明了所需写入权限；若账号或组织策略阻止写入，先检查失败提示。Pages配置参照[GitHub官方说明](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)。

每轮先测试，再恢复data分支的历史数据库，抓取后保存更新，最后发布site网页。恢复失败、数据库缺失或损坏时停止，禁止从空数据覆盖历史。推送不使用force，保存失败不发布新版网页，并尝试提供30天临时恢复备份。正常历史保存依靠data分支，不能依靠临时备份或Actions缓存。

公开源码包不含旧数据库、旧运行日志或原始页面。首次云端运行建立新历史，不导入此前本地100条记录及其首次发现时间。之后每次手动运行累计公告、修订、首次发现时间和运行日志。请勿删除data分支；误删会被视为首次运行。

云端设置 RADAR_SAVE_SNAPSHOTS=0：不保存或提交原始网页快照，日志中的snapshot字段为空。保留官方链接、HTTP状态、时间、错误、耗时等记录。该取舍减少公开内容和体积，但无法仅凭云端数据重放原始响应。默认本地运行仍可保存快照。

data分支的数据库与日志也是公开内容，只包含官方信息和技术记录。不能提交私人资料。抓取失败仍保存和发布错误日志，并把任务标为失败；若GitHub未触发、恢复/保存/发布失败或超时，网页可能是旧版，以Actions步骤和网页时间为准。确认两轮手动运行、历史延续及网页访问均正常后，再另行决定是否启用定时。

## 维护

源配置只放公开来源，不加私人条件。网站改版后修parse_list并添加相应模拟页面测试；不要通过放宽所有校验“消灭报错”。默认15秒请求超时、每次正文请求间隔0.5秒、串行访问，不重试403/429、不解验证码、不使用代理或浏览器绕过限制。栏目抓取失败继续其他来源；正文遇403/429/明确访问限制停止该来源后续正文。

第二阶段接口位于radar/extensions.py，调用会明确抛出NotImplementedError：

- PDF/Excel/Word附件解析须保留页码/单元格及原文依据。
- 后续初筛条件仅存本地私有文件，不提交公开仓库；必须检查专业、学历、教师资格、在编限制、服务期、单位同意报考和其他缺失条件。不得把初筛写成确定符合资格。第一阶段不存储具体个人条件。
- 每周简报应包括监测覆盖、失败次数、遗漏风险及原始链接；尚未实现。

## 目录

radar/core.py：请求、解析、去重、数据库、仪表盘；radar/extensions.py：未来接口；sources.json：核实过的公开来源；tests：模拟网页与网络错误测试；.github/workflows/radar.yml：默认仅手动运行的Actions/Pages配置。
